# S5 — CSV export/import

## Goal
`python -m todo export FILE.csv` writes every task to CSV; `python -m todo import FILE.csv` loads tasks from
CSV into the store. Export-then-import into an empty store reproduces the tasks exactly (ids, created, all fields).

## Interface
Module `todo/csvio.py` (stdlib `csv`); `cli.COMMAND_MODULES` gets `"todo.csvio"` appended (S2 dispatch rule).
- `COLUMNS = ("id", "title", "done", "created", "due", "priority")` — fixed export header, always all six,
  whether or not S3 is merged. Cells: id int; done `true`/`false`; `due`/`priority` = value or empty cell when
  absent/None. Rows in ascending id. UTF-8, `newline=""`, default `csv` dialect (commas, minimal quoting, CRLF).
- `export_csv(store, path) -> int` — overwrites `path`, returns number of rows written (0 -> header only).
- `import_csv(store, path) -> dict` -> `{"imported": int, "skipped": int}`.
- `register(subparsers)` adds `export FILE` and `import FILE`. Stdout: `Exported <n> tasks to <FILE>` /
  `Imported <n> tasks, skipped <m> duplicates`. Errors are `TodoError` -> `error: <msg>`, exit 1 (S2 rule).
Store (`todo/store.py`): new public `TaskStore.restore(records: list[dict]) -> dict` ->
`{"imported": [ids], "skipped": [ids]}`; one lock, one load, one atomic save, all-or-nothing.
Import rules (CSV reader opens with `encoding="utf-8-sig"`):
- Header must contain `title`; other known columns optional, in any order; unknown column, duplicate column
  or empty file -> `ValidationError`. Line numbers count the header as line 1.
- Per row: `title` via store title rules; `id` blank -> new id from `next_id`, else positive int;
  `done` blank -> false, else `true`/`false`/`1`/`0` (case-insensitive); `created` blank -> now, else must match
  `^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\dZ$`; `due`/`priority` blank -> omitted, else passed to `_validate_create`
  (so pre-S3 stores reject non-empty values as unknown fields; post-S3 they get S3 validation).
- Any invalid row -> `ValidationError("<FILE>:<line>: <reason>")`, NOTHING imported, file untouched.
- Duplicates are skipped, not errors: a row whose id already exists in the store, or repeats an earlier row's
  id in the same file, is skipped (existing task never overwritten). Blank-id rows are never duplicates.
- After import `next_id = max(next_id, max imported id + 1)`; returned tasks keep the S1/S3 dict shape.
- Missing/unreadable import file or unwritable export path -> `StoreError` (message includes the path).

Examples:
- 2 tasks -> `export out.csv` -> stdout `Exported 2 tasks to out.csv`; file line 1 `id,title,done,created,due,priority`,
  line 2 `1,Buy milk,false,2026-11-18T14:20:05Z,,normal` (S3 merged) / `1,Buy milk,false,2026-11-18T14:20:05Z,,` (pre-S3)
- `import out.csv` into a store already holding id 1 -> `Imported 1 tasks, skipped 1 duplicates`
- CSV `title,done\nA,true\n,false` -> exit 1, stderr `error: <FILE>:3: title must not be empty`, store unchanged

## Acceptance
1. Library A: add "Buy milk", add `Say "hi", world` + newline in title, complete 2 -> CLI `--file A export out.csv` exit 0, stdout `Exported 2 tasks to out.csv`; CLI `--file B import out.csv` (B empty) exit 0 stdout `Imported 2 tasks, skipped 0 duplicates`; `TaskStore(B).list() == TaskStore(A).list()`.
2. Exported header equals `id,title,done,created,due,priority`; parsing with `csv.DictReader` gives done `false`/`true` strings; empty store exports header only and prints `Exported 0 tasks to …`.
3. With S3 merged: tasks with due/priority (and one with neither) round-trip exactly (dict equality between stores).
4. Re-importing the same file into B -> `Imported 0 tasks, skipped 2 duplicates`; B unchanged. File with id 5 twice -> first imported, second skipped.
5. Import of CSV with only a `title` column (3 rows) into store with next_id 4 -> ids 4,5,6, done false, created within 5 s of now; next CLI `add` gets id 7.
6. Imported id 10 into empty store -> next `add` gets id 11.
7. Invalid rows (`done=maybe`, `id=abc`, `id=0`, `created=yesterday`, blank title, and with S3 `due=2026-02-30`) -> exit 1, stderr starts `error:` and contains `:<line>:`, no traceback; store file bytes unchanged even when valid rows preceded it.
8. Header without `title`, unknown column `color`, or empty file -> exit 1 `error:`; nonexistent import file -> exit 1 `error:` containing the path.
9. Export overwrites an existing file; export to a path in a nonexistent dir -> exit 1 `error:`.
10. UTF-8 BOM-prefixed CSV imports correctly; non-ASCII titles round-trip.
11. In-process: `export_csv(store, p) == 2`, `import_csv(store2, p) == {"imported": 2, "skipped": 0}`.
Preservation: S1 (task shape, id allocation by `add`, unknown-field rejection), S2 (dispatch, `error:`/exit codes, `list` output), S3 (validation rules, defaults) and S4 (REST shape) suites still pass; S0 both discover forms.

## Out of scope
Stdout/stdin (`-`) as file, overwrite/merge-update modes, other delimiters, JSON export, partial imports.

## Notes
- Import intentionally may restore an id below `next_id` that is not present (explicit restore); `add` still never reuses ids.
- If S3 has not landed, create `_validate_create(title, fields)` in store.py with S1 semantics; S3 extends the same helper (whoever merges second rebases).
