# S9 — README (CLI, REST API, CSV)

## Goal
PRD 11: `README.md` at the repo root documents installation-free use of the CLI, REST API and CSV
commands as they behave after S6, S7 and S8, with examples that actually run.

## Interface
Single file `README.md` (Markdown). Required `##` sections, in this order:
`Requirements`, `Quick start`, `Store file`, `CLI commands`, `REST API`, `CSV export/import`, `Running tests`.
- Requirements: Python 3.10+, standard library only, no install step (run `python -m todo` from the repo root).
- Store file: precedence `--file` > `TODO_FILE` > `~/.todo.json`; `~` is expanded in both; `--file` may be
  given before or after the subcommand.
- CLI commands: `add` (`--due`, `--priority`), `list` (`--status`, `--sort`, `--json`), `done`, `rm`,
  `edit` (`--title`, `--due`, `--no-due`, `--priority`), `export`, `import`, `serve --port`, `--version`;
  `error: <msg>` exit 1 on errors, exit 2 on usage errors.
- REST API: `serve --port N` (default 8000, host 127.0.0.1); the five endpoints; JSON fields; status codes.
- CSV: header `id,title,done,created,due,priority`; only `title` column required; import is all-or-nothing on
  invalid rows; same task (same id, created, title) is skipped as a duplicate; a row whose id is used by a
  different task gets a new id and a `Renumbered task <old> -> <new>: ...` line.
Executable-example rule: lines inside fenced code blocks that start with `python -m todo ` are runnable
examples; failing or `serve` examples are shown with a `$ ` prefix or in a ```text block instead.
Examples:
- ```sh block line `python -m todo add "Buy milk" --due 2026-12-01 --priority high` -> runs, exit 0
- ```sh block line `python -m todo edit 1 --no-due` -> runs, exit 0 (ids consistent with earlier lines)
- ```text block line `$ curl -X POST localhost:8000/tasks -d '{"title": "x"}'` -> documented, not executed

## Acceptance
1. Executable examples: every fenced-block line starting with `python -m todo ` that is not a `serve` line, run
   in document order (shlex split, `#` comments allowed) with cwd = fresh temp dir, PYTHONPATH = repo root,
   HOME = temp, TODO_FILE = <temp>/store.json -> each exits 0, no `Traceback`; at least one line each for
   `add`, `list`, `done`, `edit`, `rm`, `export`, `import`.
2. All seven required `##` headings present, in the order given in Interface.
3. Contains `python -m todo`, `3.10`, `TODO_FILE`, `~/.todo.json`, and an example with `--file` after the
   subcommand (regex `python -m todo \w+ .*--file `).
4. Mentions each subcommand and option listed under "CLI commands", including `--no-due`.
5. REST section contains `GET /tasks`, `POST /tasks`, `GET /tasks/<id>`, `PATCH /tasks/<id>`, `DELETE /tasks/<id>`
   and the codes `201`, `204`, `400`, `404`.
6. CSV section contains `id,title,done,created,due,priority`, the word `Renumbered`, and `duplicates`.
7. Contains the test command `python -m unittest discover -s tests`.
8. No source/test file changes: `git diff --stat` for the slice touches only `README.md`.
Preservation: all previously verified CLI/REST/CSV behaviors (README only documents them; no code changes).
