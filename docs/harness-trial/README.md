# Harness trial records

This folder holds the records from building `todo-app` with the
**pipelined-team-harness** skill. The skill runs Planner, Developer and QA subagent
lanes as a staggered pipeline, combining ideas from Harness-of-Harness (HoH) with
vertical slicing and critical-path scheduling.
The base project is [HarnessOfHarness](https://github.com/SomersetMaugham/HarnessOfHarness).

The work ran in two rounds:
- **Round 1 (S0–S5):** a walking skeleton, the JSON store, the CLI, due dates and priority, the REST API, and CSV export/import.
- **Round 2 (S6–S9):** fixes for the first final-QA findings. These cover the CSV import collision policy, error hardening, the `edit` command and the README.

## Contents

| Path | What it is |
|---|---|
| `brief.md` | The product request (PRD). Points 7–11 are the round-2 follow-ups the user approved. |
| `plan.json` | The slices, dependencies, areas and team shape. |
| `schedule.md` | The lane schedule generated by `harness.py schedule`. |
| `contracts/` | One contract per slice: Goal, Interface, Acceptance, Out of scope, Depends on. |
| `evidence/<slice>/` | Per-slice QA reports (`qa_report.md`, `qa_report.json`). |
| `handoff.md` | Rolling memory: the list of verified behaviors, decisions, contract changes and open items. |
| `final_qa.md`, `final_qa_round2.md` | Final QA passes, each run by a fresh subagent that judged the product against the PRD only. |
| `final_report.md` | Results, open gaps and suggested next slices. |
| `retro.md` | The orchestrator's log of friction points, which fed back into the skill. |
| `standby.md` | The standby backlog. |
| `harness.py` | The helper tool (stdlib only). It provides `validate`, `schedule`, `size`, `snapshot`, `verify`, `board` and `testguard`. |
| `SKILL.md` | The skill as revised after both rounds. |

Some reports contain absolute paths from the build workspace (`/home/claude/trial/...`).
They are kept as recorded.

## Known open items (from `final_qa_round2.md`)
1. Concurrent writers can lose updates, because the store file is not locked.
2. Importing the same foreign CSV a second time duplicates any rows that were renumbered.
3. An import can reuse the id of a deleted task.
4. Minor polish items: `HEAD /tasks` returns 501, an unpolished error for a store that is not valid UTF-8, and plural wording.
