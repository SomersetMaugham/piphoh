# S6 — CSV import conflict policy (no silent loss)

## Goal
PRD 7: `import` never silently drops a row because its id is already taken by a *different* task. Such a
row is imported under a fresh id and reported. Re-importing the store's own export is still a no-op.

## Interface
"Same task" rule (pinned; used for collisions with the store AND with earlier rows of the same file):
a record with explicit id N is the same task as the task holding id N iff the record carries an
explicit `created` (non-blank cell) AND `created` is equal AND the stripped title is equal.
`done`/`due`/`priority` are ignored for identity (mutable state; existing task always wins, never overwritten).
A record without explicit `created` is never "the same" as anything.
- Same task -> skipped (counted under "duplicates", as in S5).
- Different task on a taken id -> renumbered: it gets a fresh id, assigned like a blank-id record
  (after all non-colliding explicit ids are placed; file order; above every existing and imported id).
`TaskStore.restore(records) -> {"imported": [ids], "skipped": [ids], "renumbered": [[old, new], ...]}`
- `imported` = final ids of every inserted task in record order (includes renumbered ones' NEW ids);
  `skipped` = ids of same-task records; `renumbered` = `[old_id, new_id]` pairs in record order (lists, not tuples).
`csvio.import_csv(store, path) -> {"imported": int, "skipped": int, "renumbered": [[old, new], ...]}`
CLI `import FILE` stdout: line 1 unchanged `Imported <n> tasks, skipped <m> duplicates` (n includes renumbered),
then one line per renumbered row, in file order: `Renumbered task <old> -> <new>: id <old> is used by a different task`.
Examples:
- Store B = import of A's export; `import out.csv` again -> `Imported 0 tasks, skipped 2 duplicates` (no extra lines)
- Store holds 1 "Original" (next_id 2); CSV `id,title,done\n1,Replacement,true\n2,New,false` ->
  `Imported 2 tasks, skipped 0 duplicates` + `Renumbered task 1 -> 3: id 1 is used by a different task`;
  task 1 still `Original`/open, task 2 `New`, task 3 `Replacement`/done
- `restore([{"id":5,"title":"First"},{"id":5,"title":"Second"}])` on empty store ->
  `{"imported": [5, 6], "skipped": [], "renumbered": [[5, 6]]}`

## Acceptance
1. Store with own task 1 "existing one"; another store A with tasks 1 "Buy milk", 2 "B" exported to out.csv;
   `--file S import out.csv` -> exit 0, stdout lines exactly `Imported 2 tasks, skipped 0 duplicates`,
   `Renumbered task 1 -> 3: id 1 is used by a different task`; `list --json` titles by id: 1 "existing one", 2 "B", 3 "Buy milk".
2. Own-export no-op (S5 item 4 kept): export A, import into empty B, import again -> stdout exactly
   `Imported 0 tasks, skipped 2 duplicates`, B's store file bytes unchanged.
3. Same id + same created + same title but different done/due/priority -> skipped; existing task unchanged.
4. Same id + same title, different created -> renumbered; same id, no `created` column -> renumbered.
5. In-file repeat: `id,title\n5,First\n5,Second` into empty store -> ids 5 "First", 6 "Second";
   stdout `Imported 2 tasks, skipped 0 duplicates` + `Renumbered task 5 -> 6: ...`. Two identical rows
   with id+created+title -> second skipped.
6. Renumbered + blank-id + explicit high id mix: store next_id 3 (ids 1,2), CSV rows `1,X`(different),`,Y`,`10,Z`
   -> ids 10 Z, 11 X, 12 Y (renumbered/blank in file order after explicit ids); next `add` -> 13.
7. `restore` return: examples above match exactly (`==`); `restore([])` -> `{"imported": [], "skipped": [], "renumbered": []}`.
8. `import_csv` in-process on a fresh store -> `{"imported": 2, "skipped": 0, "renumbered": []}`.
9. All-or-nothing unchanged: invalid row after a colliding row -> exit 1 `error: <FILE>:<line>:`, store bytes unchanged.
Preservation: S5 items 1-3, 5-10 and 4's re-import half; S1 (ids never reused by `add`), S2 dispatch/`error:`
exit codes, S3 defaults/validation, S4 REST.

## Out of scope
Merge/update modes, `--dry-run`, fixing "1 duplicates" pluralisation, case-insensitive headers, `~` in CSV paths.

## Depends on
S1 (TaskStore), S2 (CLI dispatch), S5 (restore, csvio).
