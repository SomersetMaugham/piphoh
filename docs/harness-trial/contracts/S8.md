# S8 — `edit` command

## Goal
PRD 10: `python -m todo edit <id> [--title T] [--due D | --no-due] [--priority P]` changes a task's title,
due date and priority from the CLI. (README moved to S9.)

## Interface
`edit` is registered in `todo/commands.py` `register()` (no change to `cli.py` or `COMMAND_MODULES`).
- `id` positional `type=int`; `--title T`; `--due YYYY-MM-DD` and `--no-due` in an argparse mutually exclusive
  group; `--priority` with `choices=PRIORITIES`. Argparse errors (both --due/--no-due, bad priority, id `abc`) -> exit 2.
- Builds fields only from options given: `title`, `due` (`--no-due` -> `due=None`), `priority`; calls
  `TaskStore.update(id, **fields)` (S3 rules validate). No option given -> `ValidationError`
  `nothing to change (use --title, --due, --no-due or --priority)` -> `error: ...`, exit 1, store untouched.
- Success stdout: `Updated task <id>: <title>` (new title), exit 0. Unknown id -> `error: task <id> not found`, exit 1.
- `done` flag and `created` are not editable here.
Examples:
- `add "Buy milk"` then `edit 1 --title "Buy oat milk" --due 2026-12-01 --priority high` -> `Updated task 1: Buy oat milk`;
  `list` -> `1 [ ] Buy oat milk (due 2026-12-01, priority high)`
- `edit 1 --no-due` -> `list` line `1 [ ] Buy oat milk (priority high)`
- `edit 1 --due 2026-02-30` -> exit 1, stderr `error: due is not a valid calendar date: '2026-02-30'`, task unchanged

## Acceptance
1. Empty store: `add "Buy milk"`, `edit 1 --title "Buy oat milk" --due 2026-12-01 --priority high` -> exit 0 stdout
   `Updated task 1: Buy oat milk`; `list --json` task 1 has title/due/priority as given, done false, created unchanged.
2. `edit 1 --no-due` -> due null, priority untouched; `edit 1 --priority low` -> only priority changes;
   `edit 1 --title "  Trimmed  "` -> title `Trimmed`, stdout `Updated task 1: Trimmed`.
3. `edit 1` (no options) -> exit 1, stderr `error: nothing to change (use --title, --due, --no-due or --priority)`;
   store bytes unchanged.
4. `edit 1 --due 2026-02-30`, `--due tomorrow`, `--title "  "` -> exit 1, stderr starts `error:` (S3/S1 messages),
   store bytes unchanged.
5. `edit 1 --due 2026-12-01 --no-due`, `edit 1 --priority urgent`, `edit abc --title x` -> exit 2, no `Traceback`.
6. `edit 42 --title x` -> exit 1, stderr `error: task 42 not found`, stdout empty.
7. `list` after item 1 prints the S3 suffix line from the Examples; tasks other than 1 are unchanged.
Preservation: S2 add/list/done/rm output and exit codes; S3 list suffixes, validation messages, `update` semantics;
S0 usage exit 2.
