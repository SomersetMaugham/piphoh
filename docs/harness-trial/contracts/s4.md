# S4 — REST API

## Goal
`python -m todo serve --port N` runs a local stdlib HTTP server exposing the S1 store as JSON:
GET/POST /tasks, GET/PATCH/DELETE /tasks/<id>, with correct status codes (200, 201, 204, 400, 404, 405).

## Interface
Module `todo/server.py`:
- `make_server(store: TaskStore, host: str = "127.0.0.1", port: int = 0) -> http.server.ThreadingHTTPServer`
  — returns a bound, not-yet-serving server (port 0 = ephemeral; real port in `server.server_address[1]`).
  Store access is serialized (one lock) across request threads.
- `register(subparsers)` — adds `serve [--port N] [--host H]` (defaults 8000, 127.0.0.1); handler builds
  `TaskStore(args.file)`, prints `Serving on http://<host>:<port>` to stdout (flushed), serves until Ctrl-C, returns 0.
  `cli.COMMAND_MODULES` gets `"todo.server"` appended (see S2 dispatch rule).
- Every response with a body has `Content-Type: application/json`; errors are `{"error": "<message>"}`.
- Request bodies: JSON object. Allowed POST keys = `TaskStore.CREATE_FIELDS`, PATCH keys = `TaskStore.UPDATE_FIELDS`
  (S3 extends both; server must not hard-code field names beyond requiring `title` on POST).
  Validation is delegated to the store: `ValidationError` -> 400, `TaskNotFound` -> 404.

Routes:
| Method | Path | Success | Errors |
|---|---|---|---|
| GET | /tasks | 200, JSON array (= `store.list()`) | |
| POST | /tasks | 201, task JSON, header `Location: /tasks/<id>` | 400 bad JSON / non-object / missing or invalid title / unknown key |
| GET | /tasks/<id> | 200, task JSON | 404 |
| PATCH | /tasks/<id> | 200, updated task JSON | 400 bad JSON / unknown key / wrong type / `{}`; 404 |
| DELETE | /tasks/<id> | 204, empty body | 404 |
Non-integer `<id>` (e.g. `/tasks/abc`) and any other path -> 404. Wrong method on a known path -> 405 with `Allow` header.
Trailing slash tolerated (`/tasks/` == `/tasks`). Query strings ignored in S4.

Examples:
- `POST /tasks {"title":"Buy milk"}` -> 201 `{"id":1,"title":"Buy milk","done":false,"created":"2026-11-18T14:20:05Z"}`, `Location: /tasks/1`
- `PATCH /tasks/1 {"done":true}` -> 200 `{..."done":true...}`; `PATCH /tasks/1 {"done":"yes"}` -> 400 `{"error":"..."}`
- `GET /tasks/99` -> 404 `{"error":"task 99 not found"}`

## Acceptance
(Tests: `srv = make_server(TaskStore(tmp), port=0)`, run `srv.serve_forever` in a daemon thread, use `urllib.request`/`http.client`, `srv.shutdown(); srv.server_close()` in tearDown.)
1. POST /tasks `{"title":"Buy milk"}` -> 201, body has id 1, title "Buy milk", done false; then GET /tasks -> 200, array of 1 task with id 1.
2. POST response has `Location: /tasks/1` and `Content-Type` starting `application/json`.
3. GET /tasks on empty store -> 200 `[]`.
4. GET /tasks/1 -> 200 task; GET /tasks/99 -> 404 with JSON `error` containing `not found`; GET /tasks/abc -> 404.
5. PATCH /tasks/1 `{"done":true}` -> 200 done true; `{"title":"New"}` -> 200 title "New"; persisted (`TaskStore(tmp).get(1)` reflects both).
6. PATCH /tasks/1 with `{"done":"yes"}`, `{"color":"red"}`, `{}`, or body `not json` -> 400 with JSON `error`; PATCH /tasks/99 `{"done":true}` -> 404.
7. POST /tasks with `{}`, `{"title":""}`, `{"title":5}`, `[]`, `{"title":"x","bogus":1}`, or invalid JSON -> 400 JSON `error`; store unchanged.
8. DELETE /tasks/1 -> 204, empty body; then GET /tasks/1 -> 404; DELETE again -> 404.
9. GET /nope -> 404 JSON; DELETE /tasks -> 405 with `Allow` header; PUT /tasks/1 -> 405.
10. Data written via the library is visible over HTTP and vice versa (shared file).
11. CLI: `python -m todo --file tmp serve --port <free port>` as subprocess prints `Serving on http://127.0.0.1:<port>` on stdout within 5 s; GET /tasks then returns 200; terminate the process in cleanup.
12. 20 concurrent POSTs (threads) -> all 201, ids are exactly 1..20, no duplicates.
Preservation: S0, S1 (and S2 if merged) acceptance suites still pass.

## Out of scope
Auth, CORS, HTTPS, query-string filtering/sorting (could follow S3 later), pagination, PUT.
