# S2 — CLI add/list/done/rm

## Goal
`python -m todo add "title" | list | done <id> | rm <id>` on top of the S1 store, exit 0 on success,
non-zero with a clear stderr message on errors. Also fixes the CLI extension pattern S3/S4/S5 use.

## Interface
Dispatch (shared rule, frozen here):
- `todo/cli.py` keeps `main(argv=None) -> int`. Global option `--file PATH` (before the subcommand)
  selects the store file; precedence `--file` > env `TODO_FILE` > `~/.todo.json` (handled by `TaskStore(args.file)`).
- Each feature module exposes `register(subparsers) -> None` which adds its subparser(s) and sets
  `set_defaults(func=handler)`; `handler(args) -> int` (exit code), output via `print`.
- `cli.py` has `COMMAND_MODULES = ["todo.commands", ...]` (dotted names, imported and `register`ed in order).
  S2 adds `todo/commands.py` (add/list/done/rm); S4 appends `"todo.server"` (`serve`); S5 appends its module.
  S3 adds flags to `add`/`list` inside `todo/commands.py` only.
- `main` catches `TodoError`: prints `error: <message>` to stderr, returns 1. Argparse usage errors exit 2.
  No traceback is ever printed for these cases. No subcommand -> usage on stderr, exit 2 (as in S0).

Commands and output (stdout, one trailing newline):
- `add TITLE` -> `Added task <id>: <title>`
- `list` -> one line per task, ascending id: `<id> [ ] <title>` (open) / `<id> [x] <title>` (done);
  no tasks -> `No tasks.`. S3 may append extra text after the title, so tests match lines with `startswith`.
- `list --json` -> JSON array of task dicts (same shape as `TaskStore.list()`), `[]` when empty.
- `done ID` -> `Completed task <id>: <title>`; `rm ID` -> `Deleted task <id>: <title>`.
- `ID` parsed with `type=int`; non-integer -> argparse error, exit 2.

Examples:
- `python -m todo --file /tmp/t.json add "Buy milk"` -> stdout `Added task 1: Buy milk`, exit 0
- `python -m todo --file /tmp/t.json list` -> `1 [ ] Buy milk`; after `done 1` -> `1 [x] Buy milk`
- `python -m todo --file /tmp/t.json done 42` -> stderr `error: task 42 not found`, exit 1, stdout empty

## Acceptance
(All via `subprocess.run([sys.executable, "-m", "todo", "--file", tmp, ...], cwd=repo_root)` unless stated.)
1. `add "Buy milk"` exits 0 with stdout `Added task 1: Buy milk`; then `list` exits 0 and its first line starts with `1 [ ] Buy milk`.
2. `list` on empty/nonexistent file -> stdout `No tasks.`, exit 0; `list --json` -> parses to `[]`.
3. After adding A, B: `list --json` parses to 2 dicts with ids [1,2], titles [A,B], done [False,False], each having `created`.
4. `done 1` -> exit 0, stdout `Completed task 1: A`; `list` line 1 starts with `1 [x] A`, line 2 with `2 [ ] B`.
5. `rm 2` -> exit 0, stdout `Deleted task 2: B`; `list --json` ids == [1].
6. `done 42` and `rm 42` -> exit 1, stderr contains `task 42 not found`, stdout empty, no `Traceback` in stderr.
7. `done abc` -> exit 2, stderr contains `invalid`; `add` with no title -> exit 2.
8. `add ""` and `add "   "` -> exit 1, stderr starts with `error:`; no task created.
9. Env fallback: with `TODO_FILE=<tmp>` in env and no `--file`, `add X` writes to `<tmp>` (verified with `TaskStore(tmp).list()`).
10. Invalid JSON in the file -> `list` exits 1, stderr starts with `error:`, no traceback.
11. In-process: `from todo.cli import main; main(["--file", tmp, "add", "Z"]) == 0` (stdout capturable via `contextlib.redirect_stdout`).
12. CLI writes are visible to the library: after `add X` via CLI, `TaskStore(tmp).get(1)["title"] == "X"`.
Preservation: S0 and S1 acceptance suites still pass.

## Out of scope
`--status`/`--sort`/`--due`/`--priority` (S3), `serve` (S4), `export`/`import` (S5), colours, `edit` command.
