# S1 — JSON store: add/list/complete/delete (library API)

## Goal
A library API that persists tasks in a JSON file (path configurable, default `~/.todo.json`)
and supports add, list, get, complete, update and delete. This is the shared core every
other slice (CLI, REST, due/priority, CSV) builds on, so its shapes below are frozen.

## Interface
Modules: `todo/errors.py`, `todo/store.py`. Re-export from `todo/__init__.py`:
`TaskStore, TodoError, TaskNotFound, ValidationError, StoreError`.

Errors (`todo/errors.py`):
- `TodoError(Exception)` — base; `str(e)` is a human-readable message.
- `TaskNotFound(TodoError)` — attribute `task_id: int`; message `task <id> not found`.
- `ValidationError(TodoError, ValueError)` — bad title/field/type.
- `StoreError(TodoError)` — file unreadable / invalid JSON / wrong structure; message includes the path.

Task record = plain `dict` (a fresh copy each call; mutating it does not affect the store):
`{"id": int, "title": str, "done": bool, "created": str}`; `created` is UTC ISO 8601 `YYYY-MM-DDTHH:MM:SSZ`.
S3 will ADD keys (`due`, `priority`); consumers and tests must check keys by subset, never dict equality
or exact key sets.

Path resolution — `TaskStore(path: str | os.PathLike | None = None)`:
explicit `path` > env var `TODO_FILE` > `~/.todo.json` (`os.path.expanduser`). Resolved once at
construction; exposed as `store.path` (`pathlib.Path`). Tests use a temp file path.

Methods (ids are `int`; every call re-reads the file, so separate instances see each other's writes):
- `add(title: str, **fields) -> dict` — strips title; empty/whitespace or non-str -> `ValidationError`;
  any key in `fields` -> `ValidationError` in S1 (S3 adds `due`, `priority`). New task `done=False`.
- `list() -> list[dict]` — all tasks, ascending id. (S3 adds keyword-only `status=None, sort=None`; defaults keep this behaviour.)
- `get(task_id: int) -> dict` — `TaskNotFound` if absent.
- `complete(task_id: int) -> dict` — sets `done=True`, idempotent, returns updated task.
- `update(task_id: int, **fields) -> dict` — allowed keys `title` (non-empty str, stripped), `done` (must be `bool`; `1`/`"true"` rejected).
  Unknown key, wrong type, or no fields -> `ValidationError`. Missing id -> `TaskNotFound`. Order: fields validated first, then id lookup.
- `delete(task_id: int) -> dict` — removes and returns the deleted task; `TaskNotFound` if absent.
- Class constants `CREATE_FIELDS = ("title",)`, `UPDATE_FIELDS = ("title", "done")` — S3 extends; REST uses them.

Ids: start at 1, monotonically increasing, never reused (even after deleting the highest id).
File format: `{"version": 1, "next_id": int, "tasks": [task, ...]}`. Missing file = empty store (no file
created by reads). Writes are atomic (write temp file in same dir, `os.replace`); parent dir created if missing.
A `threading.Lock` guards read-modify-write within one instance.

Examples:
- `s = TaskStore(tmp/"t.json"); s.add("  Buy milk ")` -> `{"id": 1, "title": "Buy milk", "done": False, "created": "2026-11-18T14:20:05Z"}`
- `s.complete(1)["done"]` -> `True`; `s.get(99)` -> raises `TaskNotFound` (`e.task_id == 99`, `str(e) == "task 99 not found"`)
- add A (1), add B (2), `delete(2)`, add C -> C has id 3

## Acceptance
1. With a temp path: `TaskStore(p).add("Buy milk")` then a NEW `TaskStore(p).list()` returns one task with id 1, title "Buy milk", done False; the file at `p` is valid JSON.
2. `add` returns dict with keys ⊇ {id,title,done,created}, types int/str/bool/str; `created` matches `^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\dZ$` and is within 5 s of now (UTC).
3. `add("  x  ")["title"] == "x"`; `add("")`, `add("   ")`, `add(None)`, `add(5)` raise `ValidationError` (also an instance of `TodoError` and `ValueError`); `add("x", bogus=1)` raises `ValidationError`.
4. `list()` on a nonexistent path returns `[]` and does not create the file; after 3 adds, ids are [1,2,3] in order.
5. `complete(1)` returns done True; calling again still returns done True; persisted across instances.
6. `delete(2)` returns the task with id 2; subsequent `get(2)` raises `TaskNotFound` with `task_id == 2`; `list()` ids are [1,3].
7. Id non-reuse: add,add, delete(2), add -> new id 3.
8. `get/complete/delete/update` on unknown id raise `TaskNotFound`; message is exactly `task <id> not found`.
9. `update(1, title="New")` and `update(1, done=False)` persist; `update(1)`, `update(1, done=1)`, `update(1, title="")`, `update(1, color="red")` raise `ValidationError`.
10. Mutating a returned dict (`t["title"]="hack"`) does not change `get(t["id"])`.
11. Path resolution: with env `TODO_FILE=<tmp>` and no arg, `store.path == Path(<tmp>)`; explicit arg beats env; with neither (env removed, `HOME` set to a temp dir), `store.path == Path(HOME)/".todo.json"`.
12. Invalid JSON in the file -> `StoreError` on `list()`, message contains the path.
13. Parent directory created on first write (`tmp/sub/dir/t.json`).
14. `from todo import TaskStore, TodoError, TaskNotFound, ValidationError, StoreError` works.
Preservation: S0 acceptance (`--version`, both discover forms) still passes.

## Out of scope
CLI commands (S2), due/priority/filter/sort (S3), REST (S4), CSV (S5). Cross-process file locking.
